# Deployment view: Municipal Report Management System

**Takeaway:** a self-contained Java 23 Swing desktop application (one fat-less jar plus Hibernate, MySQL JDBC and forms_rt on the classpath) runs on each user's workstation and talks directly to a MySQL server (`reports_db`, port 3306) through JPA/Hibernate over JDBC. There is no application server.

Stakeholder: DevOps engineer. Detail level: **detailed** (as given). Files: `view.puml`, `view.png`, `inventory.json`.

## How the view addresses the concern
- **Runtime environments and artifacts:** Build host (Maven + JDK 23, resolving from Maven Central), JVM Java 23, the jar, `persistence.xml`, hibernate-core 6.6.50.Final, mysql-connector-j 9.4.0, forms_rt 7.0.3, MySQL server.
- **Where it runs / where data is stored:** application host (desktop) vs. database host; data lives in schema `reports_db`, user `reports_user`. Tables are generated by Hibernate (`hbm2ddl.auto=update`), but the database and user must be created first (README SQL).
- **Communication:** jar → Hibernate (JPA) → JDBC driver → MySQL over TCP 3306; build host → Maven Central over HTTPS.
- **Application–database dependencies:** persistence unit `Municipal_Report_Management_System`, JDBC URL `jdbc:mysql://127.0.0.1:3306/reports_db`, driver `com.mysql.cj.jdbc.Driver`, credentials in `persistence.xml`.

## Omitted on purpose
Internal packages (Boundary/Control/Entity/Database; a component view would show them), JUnit (test scope), transitive libraries.

## Assumptions / unconfirmed
- Database host defaults to the same machine (127.0.0.1); the URL, user and password are hard-coded in `persistence.xml`, so a remote DB requires editing the file and rebuilding. Separate-host drawing is a deployment option, not shown in code.
- Build host and Application host as separate machines is an assumption; the repo has no installer, Docker or CI file. The pom has no shade/assembly plugin or manifest main class, so how dependencies reach the classpath at run time is not defined (unconfirmed); three `main` entry points exist (HomePageGUI, UserLoginGUI, UserRegistrationGUI).
- The pom's compiler plugin uses a misspelled `<configuretion>` tag, so source/target come from the properties only.
- Credentials are default examples (`reports_password`) and must be changed outside local use.
