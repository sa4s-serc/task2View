# C4 diagrams

Verified on PlantUML 1.2026.8 with the C4-PlantUML standard library bundled in the jar (`!include <C4/...>`, offline).
Field test: context, container and component views of one system.

## Templates and macros
`puml-new c4-context`, `c4-container`, `c4-component` (the inside of one container). Argument order matters, and the
technology comes before the description:
| Macro | Arguments |
|---|---|
| `Person`, `System`, `System_Ext` | `(alias, "Label", "Description")` |
| `Container`, `ContainerDb`, `ContainerQueue` | `(alias, "Label", "Technology", "Description")` |
| `Component` (needs `<C4/C4_Component>`) | `(alias, "Label", "Technology", "Description")` |
| `System_Boundary`, `Container_Boundary` | `(alias, "Label") { ... }` |
| `Rel(from, to, "Label", "Technology")`, `Rel_L/R/U/D` | direction hints |
| `Lay_D/U/L/R(a, b)` | invisible layout link |
An empty technology (`""`) prints nothing. `SHOW_LEGEND()` must be the last line.

## House style in C4
The C4 macros draw their own fills (dark blue people, blue containers, grey externals), so `<<accent>>`, `<<alert>>`
and `<<muted>>` have no effect. Fonts, arrow colour and title still follow the house style. For emphasis use a tag;
the legend lists it automatically:
```
AddElementTag("accent", $bgColor="#1D4ED8", $fontColor="#FFFFFF", $borderColor="#1E3A8A")
Container(api, "API", "Python", "Business logic", $tags="accent")
```
`$legendText="the view is about this"` on `AddElementTag` names its legend entry (otherwise it reads "accent").
The small `▯` before each legend entry is C4-PlantUML's border-colour swatch (U+25AF), not a missing glyph.

## Layout
- **Boundary titles:** an edge that crosses the top of a `System_Boundary` runs through its centred title. Put people
  and external systems beside the boundary (`Rel_L`/`Rel_R`, `Lay_R`) rather than above it; shorten the title.
- **Container views over the slide limits:** split by path (for example the sales path and the async path) and repeat
  the shared containers (API, database) in both.
- **Judge by crossings and the PNG, not the ratio alone:** a full container view left to right reached 1.34 with 5
  crossings and long diagonals; top to bottom was 1.17 with 2 and read better.
- Left to right context views: `skinparam ranksep 110` moved edge labels off the node corners (1.44 to 1.57).
- Two parallel edges to the same target (two apps sign in to one IdP): label one, give the other `" "`.
- A wide row of leaf containers in a top-down print view: reverse one edge with `Rel_U(worker, queue, "Consumes")` so
  that node moves above its neighbour (2.30 to 1.32 in the field test). `Lay_D` hidden links alone reached 1.82.
- If no lever keeps edges off a boundary title, drop the boundary on the slide view and say so; keep it in print.
