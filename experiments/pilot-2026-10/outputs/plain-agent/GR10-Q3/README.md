# Architecture views for the persistence layer (GR10-Q3)

Audience: a database engineer who will change persistence to support future report-management changes.
All content comes from `src/main/java/Entity`, `Database`, `Control`, `Boundary` and `META-INF/persistence.xml`.

- **view-1.puml - Persistent data model.** The five tables (`users`, `reports`, `status_updates`, `internal_notes`, `notifications`), their columns, keys, nullability, cardinalities and cascade rules. It shows how users, reports, locations, categories, states, state changes, notes and notifications are related. It also shows what is *not* a table: category (enum stored as text), state (`current_status` string) and location (embedded columns in `reports`); the user roles share one table via a discriminator. Needed because the schema is generated by Hibernate (`hbm2ddl=update`, no DDL files), so the entity classes are the only schema definition.
- **view-2.puml - Report lifecycle and persisted data.** The state machine submitted -> assigned -> in_progress -> resolved, with the rows inserted or updated at each transition, which states trigger a notification, and how notes fit in. It shows what must be kept over a report's life (append-only history, assigned operator, editable flag) and a transactional gap: the notification is saved in a separate transaction after the status change.
- **view-3.puml - Dependencies on persisted data.** The GUIs, the controllers, the two domain services and `PersistenceService`/`JpaUtil`, with the queries each use case runs. It shows which application parts break if a table or field changes. All database access goes through `UserService`/`ReportService` and `PersistenceService`; queries use field-name strings in JPQL, so a rename is not caught at compile time. `UserLoginGUI` uses its controller directly; the other GUIs go through `SystemServicesController`.

Observations (from code): passwords are stored as plain text; no DB-level check that `citizen_id`/`operator_id` point at the right role; the DB does not constrain `current_status`/`category` values (text columns).
